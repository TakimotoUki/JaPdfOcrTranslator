# 术语表策略手册（glossary_policy.md）

> 对应 `config.json.params.glossary_policy` 的 A/B/C/D 四种情形。
> 判定由调用方（Swift `GlossaryPolicy.resolve`）推好并写进 config，**Agent 不自行推导**，
> 只按本手册执行。锁与冲突的权威语义在 `glossary_tool.py`（§4.2 upsert 判定表）。

## 总纲

- **锁定词条**（`locked=true`，通常 `origin=user`）：优先级最高，**任何情况下不得改写**。
  你给出与锁定词条不同的译名会被系统丢弃并记为 `rejected_by_lock`，出现在质量报告里。
- **自动词条**（`origin=auto`）：软件维护，遇到新专名请补入；已有条目优先沿用现值。
- 同一 source 出现不同译名时，系统**保留现值并记冲突**，绝不静默覆盖。
- `SOURCE_ONLY_TYPES = {称谓, 敬称, 口癖, 固定表达}`：这四类**只按 source 匹配，忽略 aliases**
  （避免裸名 alias 把带语气的派生译法注入普通称呼）。

---

## 情形 A · 纯用户表（锁定，禁新增）

触发：有用户表 + 自动补充关闭。

### 正例
1. 表中写 `御堂 静 → 御堂静`，译文里所有出现处一律写「御堂静」。
2. 遇到未入表的专名（如新出场角色「氷室」），沿用其前文首次译法，不新建词条。
3. 认为某专名应当入表时，用 `state_tool.py event --type glossary_suggestion` 留只读建议，
   不改表、不调用 `upsert`。

### 反例
1. **调用 `glossary_tool.py upsert` 新增词条** → 被 `rejected_by_policy` 丢弃，且违反本情形语义。
2. 把表中「御堂静」改成自己觉得更好的「御堂 静」→ 锁定词条被改写（`rejected_by_lock`）。
3. 同一角色前半本书写「冰室」、后半本写「冰川」→ 违反「沿用首次译法」的一致性要求。

---

## 情形 B · 用户表锁定 + 自动补充（默认路径之一）

触发：有用户表 + 自动补充开启。

### 正例
1. 译前对第 N 块先做 `upsert --phase pre`（即使无新词也以 `{"terms":[]}` 调用），
   然后只使用 `hits` 给出的【本块命中术语】子集翻译。
2. 新专名补入自动词条（`origin=auto`），后续块沿用该译名。
3. 翻译完成后用「原文 + 译文」做 `--phase post` 回抽，依据译文**实际采用**的写法校准。

### 反例
1. 跳过 `--phase pre` 直接翻译 → F33-02 不达标，`verify` 退 5，报告列出缺失块号。
2. 对锁定词条「御堂 静」给出不同译名 → `rejected_by_lock`，你的译名被丢弃。
3. 把全部术语（含用户词条）一次性塞进每一块的提示词 → 应只注入本块命中子集。

---

## 情形 C · 全自动术语表（默认路径之一）

触发：无用户表 + 自动补充开启。

### 正例
1. 首块起自行建表：新专名 → `upsert --phase pre` 写入，后续块沿用同一译名。
2. 同一 source 出现不同译名时，优先沿用现值；确需新译名也只记冲突、不改表。
3. 回抽时依据译文实际写法填 `target`，不凭空创造译名。

### 反例
1. 同一角色第一块译「樱坂」、第十块译「樱之丘」→ 违反「首次确定的译法即为基准」。
2. 把普通寒暄、通用词汇、一次性修辞也入表 → 污染术语表，QA 术语符合率下降。
3. 对已存在 source 静默覆盖为另一译名 → 系统会记冲突；不要尝试绕过。

---

## 情形 D · 不维护术语表（降级逃生口）

触发：无用户表 + 自动补充关闭。

### 正例
1. 仅凭上下文保持译名前后一致。
2. 不调用任何 `glossary_tool` 写库命令。

### 反例
1. 调用 `upsert` 建表 → 全部被 `rejected_by_policy` 丢弃，白耗调用。
2. 声称「不维护术语表」却把专名译得前后不一 → 违背用户对一致性的最低期待。

---

## 冲突裁决速查（S7）

- 锁定词条冲突：**不许裁决**，只留 `rejected_by_lock` 证据（创建即 `resolved=true`）。
- 自动词条冲突：`glossary_tool.py conflicts --state $STATE` 查看；
  `resolve --source S --take proposed|existing` 裁决（`--by user` 表示用户裁决）。
- S7 自检：`glossary_tool.py conflicts --state $STATE --fail-if-open` 退 5 表示仍有未决冲突。
